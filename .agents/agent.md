# Agent 通用工作说明

## 1. 项目定位

本项目用于维护后端、后台管理端、前台用户端、小程序与 APP 四个相互独立的工程。

规范分两个阶段使用：

- 脚手架初始化阶段只维护代码工程规范：`.agents/代码工程规范/`。执行任务的 agent 不需要读取或维护 `工作流/`、`排期进度/`、`产物/` 下的流程产物，也不按 Spec 周期推进。
- 业务实现阶段按 `.scratch/<feature>/spec.md` 与 `.scratch/<feature>/issues/` 票据推进；先读对应 spec，再按票据实现、自检与交付。

## 2. 多端工程

项目包含 4 个相互独立、可启动、可构建、可联调的工程：

| 端侧 | 目录 | 技术栈 |
|------|------|--------|
| 后端 | `server-api` | SpringBoot |
| 后台管理端 | `backend-ui` | Vue3 + Element Plus + Vite |
| 前台用户端 | `frontend-ui` | Vue3 + Vite |
| 小程序与 APP | `uniapp-ui` | uni-app（Vue3）+ uni-ui |

各端目录直接位于项目根目录。`uniapp-ui` 遵守 `代码工程规范/UniApp小程序与APP项目分层规范.md`，依赖安装须使用工程内 `.npmrc` 的 `legacy-peer-deps` 约定。

## 4. 代码生成原则

- 脚手架初始化阶段优先维护工程骨架和通用基础能力；已立项业务按 `.scratch/<feature>/spec.md` 与票据实现。
- 脚手架初始化阶段不要生成商城、订单、库存、博客、CRM、OA 等业务模块；已立项业务按 `.scratch/<feature>/spec.md` 与票据实现。
- 脚手架初始化阶段不创建业务表；已立项业务的建表与初始化遵循规格与数据库脚本。
- 后端可提供健康检查、统一返回、异常处理、跨域配置、基础认证壳等通用能力。
- 后台管理端可提供登录壳、基础布局、路由、请求封装、空仪表盘和系统空状态。
- 前台用户端可提供首页壳、基础布局、路由、请求封装和系统空状态。
- 前端统一使用 JavaScript，不使用 TypeScript。
- 前台和后台样式统一接入 Tailwind CSS。
- 前台和后台时间处理统一使用 `moment@2.29.4`。
- 前台和后台默认内置图表 `echarts@5.5.1` 和富文本 `aieditor@1.3.3`。
- 前台和后台登录 Token 状态使用 Pinia，并通过 `pinia-plugin-persistedstate@3.2.1` 持久化。
- 后端金额字段如后续出现，按当前规范使用 `Double`。
- Windows 终端命令默认使用 PowerShell 7，即 `pwsh`。
- 新增临时产物统一写入项目根目录 `temp/`。
- 不需要 Swagger、OpenAPI、Knife4j。

## 5. 自检原则

- 自检优先运行 `scripts/check.ps1`；不启动长期 dev server，必须启动时后台运行并把输出写入 `temp/*.log`。
- 各端搭建完成后，必须分别执行可用的安装、构建、测试或启动验证。
- 需要浏览器验证时，执行任务的 agent 自己选择未占用端口启动服务，避免影响用户已有服务。
- 自检完成后，只关闭本次任务启动且不再需要的服务；不得误关用户服务。
- 最终回复说明涉及端侧目录、启动命令、验证结果和未完成事项。
