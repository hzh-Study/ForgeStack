# MCP 数据库操作通用规范

## 1. 范围与连接

- 仅操作当前任务需要的库、表和数据，不为演示提前创建业务表或插入业务模拟数据。
- 连接信息优先采用用户当前提供的配置，否则读取 `server-api/src/main/resources/application.yml` 的 `spring.datasource`；从 JDBC URL 解析主机、端口和库名，不沿用其他项目配置。
- 优先使用当前会话已连接的数据库 MCP，先确认目标数据库及工具的读写能力。
- 只有确需配置新的 MCP 连接时才维护当前客户端支持的配置文件；不因项目缺少 `.mcp.json` 重复配置已有连接。
- MCP 不可用、只读或结果异常时，可使用本机 MySQL 客户端补充当前已授权的操作，并说明原因。先检查 PATH、常见安装目录或用户提供的客户端路径。
- 所有可用连接方式均失败时，停止依赖数据库的操作，说明实际错误及缺失信息，继续处理不依赖连接的工作；不声称数据库操作已完成。

## 2. 操作流程

1. 明确操作目的、目标库表和影响范围。
2. 查询现有库、表、字段、索引和相关数据，避免重复创建或覆盖。
3. 结构变更前说明用途、字段、类型、必填项、默认值及索引；改表还需说明已有数据的兼容与迁移方式。
4. 按需分步创建或修改对象，再写入必要数据，不把无关变更混在一次操作中。
5. 每次建库、建表、改表或写入数据后查询核对实际结果；涉及代码时同步核对 Entity、DTO、VO 和前端字段。

## 3. 库表与数据规则

- 新建 MySQL 库默认使用 `utf8mb4` 和 `utf8mb4_unicode_ci`，已有库沿用当前配置，除非任务要求调整。
- 表名和字段名使用小写下划线，沿用项目已有前缀，名称简短且含义清晰；不为简化名称擅自重命名已有表。
- 表备注使用简短业务名称，通常为 2～10 个中文字符；详细含义写入字段备注或设计说明。
- 基础字段、枚举存储和删除策略遵守 `SpringBoot通用项目结构规范.md` 第 7.3、10、18 节。
- 索引按实际查询和唯一性约束设计，不为每个字段默认添加索引。
- 初始化数据只写入任务明确需要的账号、菜单、角色等基础数据；业务数据按用户明确要求处理。
- 演示、测试和模拟账号的登录密码统一使用 `123456789`，用户另有指定时除外；数据库保存密码摘要和盐值，不能保存明文。

## 4. 中文 SQL 编码

本机 MySQL 客户端执行包含中文备注或数据的 SQL 时：

- 客户端显式设置 `--default-character-set=utf8mb4`，SQL 文件首行使用 `SET NAMES utf8mb4;`。
- 较长 SQL 保存为 UTF-8 文件再通过 `SOURCE` 执行，临时文件按 `终端命令执行规范.md` 存放。
- 执行后查询 `INFORMATION_SCHEMA.TABLES`、`INFORMATION_SCHEMA.COLUMNS` 和相关数据，核对表备注、字段备注与中文内容；出现乱码先修复再交付。

备注核对示例（替换为已确认的库名）：

```sql
SELECT TABLE_NAME, TABLE_COMMENT
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA = '当前库名';

SELECT TABLE_NAME, COLUMN_NAME, COLUMN_COMMENT
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = '当前库名'
ORDER BY TABLE_NAME, ORDINAL_POSITION;
```

## 5. 影响范围与交付

- 删除库、清空表、无条件更新、批量删除或修改历史数据等高风险操作，必须有用户明确授权，并在执行前说明影响范围。
- 不扩展用户授权的库表或数据范围；连接密码不得写入交付说明或临时日志。
- 交付时说明实际变更对象、查询验证结果和未完成事项；仅交付 SQL 文件而未执行时，应明确说明。
