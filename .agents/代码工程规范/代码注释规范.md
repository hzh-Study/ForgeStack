# 代码注释规范

## 1. 文档目的

本文档用于约束后续生成或修改代码时的注释规则。

注释的目标是帮助毕业设计阅读、答辩讲解和后续维护。注释要解释业务含义、接口用途、字段含义和关键逻辑，不要机械重复代码本身。

## 2. 通用要求

后续生成或修改代码时，必须补充必要中文注释。

通用规则：

- 重要类、接口、方法、字段、枚举值必须写中文注释。
- 复杂业务逻辑、权限判断、状态流转、金额计算、库存计算必须写说明性注释。
- 注释应说明“为什么这样做”和“业务含义是什么”，避免只翻译代码。
- 注释必须和代码保持一致，修改代码时同步修改相关注释。
- 不写无意义注释，例如“设置名称”“返回数据”这类和代码完全重复的内容。

## 3. 后端注释要求

### 3.1 类注释

以下后端类必须写类注释：

- Controller
- Service
- ServiceImpl
- Mapper
- Entity
- DTO
- VO
- Enum
- Config
- Util
- Exception

示例：

```java
/**
 * 管理员与用户共用的登录控制器
 */
@RestController
public class AuthController {
}
```

### 3.2 方法注释

以下方法必须写方法注释：

- Controller 对外接口方法。
- Service 业务方法。
- Mapper 自定义方法（数据库访问方式遵守后端规范）。
- Util 公共工具方法。
- 涉及登录、权限、订单、库存、支付、售后、审核、状态变更的方法。
- **ServiceImpl 中自行声明的每一个方法都必须写 Javadoc**，包括 `public`、`protected`、`private` 方法，以及重写方法、查询条件构造、参数校验、数据转换、递归收集、格式化和兜底方法；不能以“方法简单”“接口已有注释”或“私有方法”为理由省略。
- ServiceImpl 的依赖注入构造方法也要写 Javadoc，并为每个依赖补充 `@param` 说明。

方法注释应包含：

- 方法用途。
- 关键参数含义。
- 返回结果含义。
- 必要时说明业务限制或异常场景。

示例：

```java
/**
 * 管理员登录
 *
 * @param dto 登录账号和密码
 * @return 登录后的 Token 和管理员基础信息
 */
public Result<LoginVO> login(@Valid @RequestBody LoginDTO dto) {
}
```

### 3.3 字段注释

以下字段必须写注释：

- Entity 字段。
- DTO 字段。
- VO 字段。
- Enum 枚举值和属性。
- 配置类中的关键配置字段。
- `static final` 常量，特别是权限标识、缓存 key、配置 key、业务开关等。

字段注释属于逐字段硬性要求：

- DTO、VO、Entity 中的**每一个字段**都必须在字段正上方写独立的中文 Javadoc，不能只写类注释后连续声明无注释字段。
- 注解不能代替字段注释，`@NotNull`、`@Size`、`@TableId` 等注解上方仍要保留字段 Javadoc。
- 不允许因为同类中其他字段已有注释，就省略剩余字段注释。

示例：

```java
/**
 * 管理员账号
 */
private String username;

/**
 * 账号状态。
 */
private EnableStatusEnum status;
```

常量注释要求：

- 常量必须说明业务含义，不能只写变量名翻译。
- 状态等有限值的定义遵守后端枚举规范，此处只规定注释格式。

示例：

```java
/**
 * 管理端登录 Token 请求头名称。
 */
private static final String ADMIN_TOKEN_HEADER = "Authorization";

/**
 * 登录验证码缓存前缀，用于隔离验证码和其他缓存数据。
 */
private static final String CAPTCHA_CACHE_PREFIX = "captcha:";
```

### 3.4 枚举注释

枚举类必须说明枚举用途，枚举值必须说明业务含义。

枚举值注释属于逐项硬性要求：每一个枚举常量都必须在常量正上方写独立的中文 Javadoc，不能只给枚举类写总注释，也不能用一条行尾注释概括多个枚举值。

示例：

```java
/**
 * 订单状态枚举
 */
public enum OrderStatusEnum {

    /**
     * 待支付
     */
    WAIT_PAY("WAIT_PAY", "待支付");
}
```

## 4. 前端注释要求

### 4.1 API 方法注释

`api` 目录下的接口方法必须写注释。

示例：

```js
/**
 * 管理员登录
 *
 * @param {Object} data 登录表单参数
 * @returns {Promise} 登录结果
 */
export function login(data) {
  return request.post('/auth/login', data)
}
```

### 4.2 Model 注释

`models` 目录中的默认表单、默认查询参数、字段转换方法必须写注释。

示例：

```js
/**
 * 商品列表默认查询条件
 */
export const defaultProductQuery = {
  keyword: '',
  status: '',
  pageNum: 1,
  pageSize: 10
}
```

### 4.3 Store 注释

`stores` 中的跨页面共享状态和 actions 必须写注释，特别是：

- Token 保存。
- 登录状态清理。
- 当前用户信息。
- 权限菜单。
- 全局设置。

### 4.4 页面与布局方法注释

Vue 页面和布局组件中的方法必须写 JSDoc 注释。不能因为方法名看起来清楚就省略注释。

以下方法必须写注释：

- 初始化数据加载，例如 `loadData`、`fetchDetail`、`initPage`。
- 查询、搜索和重置，例如 `handleSearch`、`handleReset`。
- 新增、编辑、详情、弹窗打开和弹窗关闭，例如 `openCreate`、`openEdit`、`openDetail`。
- 表单提交和保存，例如 `handleSave`、`handleSubmit`。
- 删除、批量删除、重置密码、状态变更等写操作。
- 文件上传、图片上传、头像上传、上传回显和文件路径转换。
- 登录、退出、Token 保存、账号信息恢复。
- 权限判断。
- 表单提交前的数据转换。
- 表格筛选参数组装。
- 订单状态、支付状态、售后状态流转。
- 金额、库存、优惠券、运费等计算。
- 图片上传、素材适配、效果图还原中的特殊处理。
- 非显而易见的交互逻辑。

注释内容应说明“这个方法处理什么业务动作”和“为什么要做关键转换”，例如空字符串状态转换为 `null`、上传后只保存相对路径、编辑前复制行数据避免污染表格等。

## 5. 不强制注释的情况

以下内容不强制写注释：

- 简单 `import`。
- 简单变量赋值。
- 普通 CSS 类名。
- 与代码完全重复的废话注释。
- 临时局部变量且业务含义很清楚的代码。

## 6. 注释语言和格式

- 默认使用中文注释。
- 技术关键字、接口路径、字段名、类名可以保留英文。
- Java 类、方法、字段使用 Javadoc 风格注释。
- JavaScript 函数和重要对象使用 JSDoc 风格注释。
- Vue 模板中尽量少写注释，优先在脚本逻辑中说明。

## 7. 代码提交前检查

每次代码任务完成前，需要检查新增代码是否符合本注释规范。

如果发现关键类、方法、字段没有注释，应先补齐注释，再进行构建、联调和验收。

检查时至少逐项确认：

- 本次新增或修改的 DTO、VO、Entity 是否每个字段都有独立 Javadoc。
- 本次新增或修改的 Enum 是否每个枚举值都有独立 Javadoc。
- 本次新增或修改的 ServiceImpl 是否每个构造方法和每个方法都有 Javadoc。
- 本次新增或修改的 Controller、Service、前端 API 与 Vue 页面方法是否满足对应注释要求。

上述检查未通过时，不得宣称代码已完成或进入最终交付。
