# 工程代码执行约束规范

## 1. 任务范围

- 直接按用户当前目标实现、验证和交付，不按页面周期或 Spec 排期推进。
- 仅修改任务涉及的端侧和必要关联文件，不做无关重构，不提前生成未来业务模块。
- 未要求具体业务时，优先维护布局、登录、请求封装、统一返回、异常处理等基础能力。
- 不维护 `工作流/`、`排期进度/`、`产物/` 流程目录，不为页面周期开启子 agent。

## 2. 工程边界

- 各端目录以 `.agents/agent.md` 为准，后端、后台、前台、小程序与 APP 分别保持独立工程。
- 页面、路由、布局和组件只在当前前端工程内组织与复用，不跨端混放。
- 后端遵守 `SpringBoot通用项目结构规范.md`；两个前端分别遵守各自分层规范；小程序与 APP 端遵守 `UniApp小程序与APP项目分层规范.md`。
- 前端统一使用 JavaScript，不使用 TypeScript。
- 不引入 Swagger、OpenAPI、Knife4j。

## 3. 代码排版

- 使用可阅读的多行排版，不把多个独立语句、完整方法或控制结构挤在一行。
- 分号遵循语言语法和工程现有风格；不使用“遇到分号就换行”的机械替换，保留正常的循环头部和字符串。
- Java 方法体展开，控制结构使用花括号并按四个空格缩进；注解独立成行，方法之间留空行。
- 前端遵循现有缩进与分号风格，Vue 模板按结构换行。简单表达式、短回调和对象可保持紧凑写法。
- 短参数列表、简单条件和短链式调用可保持单行，较长表达式按逻辑折行。
- 修改后复核差异，避免格式化改变字符串、SQL、正则表达式或业务行为。
- 注释统一遵守 `代码注释规范.md`。

## 4. 专项操作

- 执行终端命令、存放临时产物、启动或清理服务时，遵守 `终端命令执行规范.md`。
- 涉及数据库连接、结构或数据操作时，遵守 `MCP数据库操作通用规范.md`；不为演示擅自建表或插入业务模拟数据。
- 页面实现和验收遵守 `页面实现与自检交付规范.md`。
- 涉及效果图或图片生成、压缩、接入时，另读 `页面设计与素材处理规范.md`。常规页面调整不强制要求效果图。

## 5. 验证与交付

- 按改动范围执行必要验证：后端编译、测试或启动，前端构建及相关页面浏览器验收，小程序与 APP 端按 `UniApp小程序与APP项目分层规范.md` 的自检验收执行。
- 只验证涉及的端侧；各端均有改动时分别验证。仅修改规范文档时检查内容、引用和差异，无需构建业务工程。
- 交付时说明修改内容、实际验证结果及未完成事项；页面任务按页面验收规范补充地址和操作结果。
- 不将未执行、失败或受阻的检查写成通过。
